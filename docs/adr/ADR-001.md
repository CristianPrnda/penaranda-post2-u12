# ADR-001: Arquitectura Hexagonal para aislar el dominio

## Estado: Aceptado — 2026-05-20

## Contexto

El sistema de pedidos debe soportar multiples tipos de procesamiento y canales de
notificacion. El acoplamiento directo del servicio a Spring Data JPA y JavaMailSender
dificulta las pruebas unitarias y hace costoso cambiar la implementacion de
infraestructura. El servicio legacy `ServicioPedidosLegacy` mezcla logica de negocio,
persistencia y notificacion en un solo metodo, con CC=4 y Cognitive Complexity=6.

## Decision

Se adopta Arquitectura Hexagonal. El dominio define puertos (interfaces puras en
`dominio/puertos/`). Los adaptadores e infraestructura implementan los puertos.
El dominio no importa ninguna clase de Spring ni de JPA directamente.
Las reglas de esta decision son verificables con ArchUnit (regla `dominioAislado`).

## Consecuencias

**Positivas:**
- El dominio es testeable con Mockito sin levantar contenedor Spring.
- Cambiar de JPA a MongoDB requiere solo un nuevo adaptador, sin tocar el dominio.
- Las pruebas unitarias de procesadores no necesitan base de datos.

**Negativas:**
- Mas interfaces y clases de mapeo que en MVC clasico.
- Curva de aprendizaje para desarrolladores acostumbrados a arquitectura en capas.
- El trazado de flujo requiere seguir la cadena puerto → adaptador → infraestructura.
